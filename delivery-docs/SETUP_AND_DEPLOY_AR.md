# إعداد الخدمات والنقل

## استخدام النسخة المنشورة الحالية

الحزمة مصدر برمجي وليست نسخة احتياطية للبيانات. باستخدام مشروع Supabase الحالي تستمر الحسابات والبلاغات الموجودة. لا تعيدي تنفيذ migrations الأولية على مشروع قائم؛ هي مخصصة للإنشاء مرة واحدة، والتعديلات مطبقة بالفعل على المشروع الحالي.

`.openai/hosting.json` يحتفظ بهوية الموقع الحالي. هوية المشروع ليست مفتاح دخول. لا تنشري نسخة تجريبية فوق الموقع الأصلي بلا قصد؛ عند إنشاء موقع مستقل جديد اضبطي هوية نشر مستقلة وفق منصة الاستضافة.

## إعداد مشروع Supabase جديد

1. أنشئي مشروعًا جديدًا واختاري المنطقة والإعدادات المناسبة.
2. طبّقي الملفات التالية بالترتيب، عبر مسار migrations أو SQL Editor في مشروع فارغ مخصص لهذا التطبيق:

   1. `supabase/migrations/202610310001_mirsad.sql`
   2. `supabase/migrations/20261031175901_triage_review_fallback.sql`
   3. `supabase/migrations/202611010001_ticket_contact.sql`
   4. `supabase/migrations/202611010002_notifications.sql`

3. راجعي الجداول والسياسات والدوال والصلاحيات بعد التطبيق. لا تعطي الواجهة مفتاح `service_role`.
4. فعّلي تأكيد البريد. في Auth URL Configuration ضعي أصل التطبيق الفعلي في Site URL، ومسارات العودة المسموح بها لتأكيد البريد واستعادة الحساب.
5. أثناء التطوير أضيفي أصل localhost المناسب إلى allowlist. قبل الإطلاق اضبطي SMTP مناسبًا لبريد المؤسسة واختبري الرسائل من خارج حساب المالك.
6. ضعي `SUPABASE_URL` و`SUPABASE_ANON_KEY` في متغيرات الخادم/الاستضافة. هذه القيم العامة تذهب للمتصفح لتهيئة SDK؛ حماية البيانات تعتمد على Auth وRLS.

## وظيفة الذكاء الاصطناعي

الملفات الأربعة في `supabase/functions/mirsad-triage/` مطلوبة معًا:

- `index.ts`: قراءة أسرار البيئة وتشغيل Deno HTTP server.
- `handler.ts`: توثيق المستخدم، حجز مهمة التحليل، طلب Groq، التعامل مع الأخطاء وحفظ النتيجة.
- `triage.ts`: تعليمات النموذج وschema والتحقق من ناتجه.
- `deno.json`: إعداد dependency.

من Dashboard مشروع Supabase خزّني السر `GROQ_API_KEY`. المتغير `GROQ_MODEL` اختياري، والافتراضي الموجود في الكود `openai/gpt-oss-120b`. مفاتيح Supabase الخدمية داخل Edge Function تأتي من بيئة Supabase، وليست من الواجهة.

باستخدام Supabase CLI الرسمي، بعد إعداد الأداة وتسجيل الدخول وربط المشروع المختار، يكون أمر النشر:

```sh
supabase functions deploy mirsad-triage --project-ref YOUR_PROJECT_REF --no-verify-jwt
```

هذا الخيار جزء من تصميم الوظيفة الحالي: هي تتحقق بنفسها من كل JWT عبر Auth `/user` قبل التصنيف، ويوجد GET `/health` عام لا يكشف أسرارًا. لا تعممي تعطيل تحقق JWT على وظائف أخرى بلا فحص.

يمكن أيضًا نشر محتوى الوظيفة من مسار Edge Functions المدعوم في Dashboard مع ملفاتها وتبعياتها الصحيحة. لا تنسخي ملف `index.ts` وحده وتتركي الملفات التي يستوردها.

فحص الجاهزية:

```text
https://YOUR_PROJECT_REF.supabase.co/functions/v1/mirsad-triage/health
```

`ready:true` يثبت توفر إعدادات الوظيفة ووصولها إلى النموذج في فحص الجاهزية؛ لا يثبت نجاح طلب توليد أو توفر الحصة في كل لحظة. أنشئي بلاغ تجربة من حساب مسجل للتحقق من المسار كاملًا وراجعي تصنيفه وسببه. خطط التجربة لدى المزوّد لها حدود وقد تتغير؛ لا يوجد ضمان استخدام غير محدود.

## أول مسؤول واعتماد الفنيين

سجّلي الحساب المقصود وأكّدي بريده أولًا. بعد التحقق يدويًا من هويته وUUID الصحيح، يقوم مالك مشروع قاعدة البيانات بترقيته:

```sql
update public.profiles
set role = 'admin'
where id = '<VERIFIED_AUTH_USER_UUID>';
```

استبدلي العنصر النائب بالمعرف المتحقق منه، لا باسم أو بريد متوقع. بعد ذلك سجّلي الدخول بالحساب الإداري واعتمدي طلبات الفنيين من لوحة التحكم. لا توجد كلمة مرور افتراضية أو ترقية ذاتية أو حساب تجريبي إداري داخل الحزمة.

## نقل الاستضافة

النسخة الحالية تعتمد على Vinext وCloudflare Workers وطبقة Sites المرفقة. حفظ المشروع في ZIP لا يحوله إلى برنامج سطح مكتب، وGitHub Pages وحده لا يشغل API أو يحفظ الأسرار.

- للحفاظ على نفس البيئة: استخدمي بناء ونشر Sites مع هوية المشروع الصحيحة.
- للاستضافة في بيئة أخرى: يحتاج المطوّر مراجعة runtime وقراءة environment variables وتهيئة Worker ومسار البناء ومكوّنات Sites؛ لا تحذفيها عشوائيًا.
- عند تغيير أصل الموقع: حدّثي إعدادات Supabase Auth URL والعودة، ومتغيرات الاتصال، ثم اختبري الدخول وتأكيد البريد واستعادة الحساب من الأصل الجديد.
- قبل أي إطلاق مؤسسي: اختبري الصلاحيات بحسابات منفصلة، واضبطي البريد والنسخ الاحتياطي والمراقبة وحصص الخدمات.

## ما الذي لا تنقله الحزمة؟

- الحسابات وكلمات المرور والسجلات الفعلية.
- أسرار Groq أو Supabase أو جلسات المستخدمين.
- إعدادات مشروع Supabase وحصصه وSMTP وredirect allowlist كحالة تشغيلية؛ تضبط في المشروع المقصود.
- ملكية عنوان الموقع أو domain جديد.
